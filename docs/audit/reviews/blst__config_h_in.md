## Purpose and trust boundary

This template is the single compile-time feature contract generated by CMake
for the native library. It conveys scalar/assembly/ADX, native and portable
AVX-512, experimental CUDA, platform support, and the fixed limb width to every
translation unit. It must reflect configuration decisions only; it must not
perform runtime CPU dispatch, select CUDA implicitly, or permit an unsupported
platform or representation to compile silently.

No secret or caller data crosses this boundary. Its security impact comes from
ensuring every translation unit agrees on representation, enabled instruction
sets, and supported-platform gates.

## Contracts and invariants

- CMake is the only supported generator of `config.h`.
- `BLST_LIMB_SIZE` is exactly decimal `64`; root CMake rejects every other
  cache value before generating this file.
- Native AVX-512 and portable AVX-512 are independent compile-time features;
  `BLST_DEFAULT_AVX` selects the production implementation without runtime
  dispatch.
- Apple Silicon is the supported AArch64 target. Other ARM64 and CHERI require
  their explicit experimental override; CUDA requires explicit opt-in.
- C/C++ linkage and CUDA host/device decoration macros change declarations but
  do not own state, memory, or control flow.

## Dependency and call-path map

The root CMake project configures this template into a build-directory header.
`blst/common/defines.h` includes that result and is the fan-out point for limb
types, vector layouts, and compiler attributes. Backend and public-adapter
translation units consume the same generated values. Rust reaches the selected
native library through C declarations; it does not parse the template itself.
